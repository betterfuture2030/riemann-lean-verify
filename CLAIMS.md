# Claims ledger

Every claim this repository makes, with the kind of evidence behind it, how to reproduce it, and its state. If a claim here cannot be reproduced as described, that is a bug in this repository: please open an issue.

Status as of 2026-11-26; the tiers and most of the rows date from 2026-11-20. The verdict criteria are fixed in [`PREREGISTRATION.md`](PREREGISTRATION.md).

## Evidence tiers

| Tier | Meaning | Who can re-check it |
|---|---|---|
| **S** | Script-reproducible. A deterministic check on the downloaded source; no compiling. | Anyone, in minutes, on a laptop |
| **K** | Kernel-checked. The Lean kernel accepted something; requires compiling the modules involved. | Anyone with the toolchain; cost depends on how many modules |
| **M** | Measured. Timings, memory, disk, prices. Depends on the machine or the date. | Anyone, on their own machine; expect different numbers |
| **R** | Reading. Statements about what the source says, produced by AI agents with adversarial review and spot checks. | By hand, using the pointers given; not mechanically |

**No conclusion in this repository rests on tier R.** Reading is used to navigate and to decide what to check. The verdict rests on tiers S and K only.

## What has not been checked

Neither of Lean's kernels has been run on the export without the allocator setting. `lean4lean` and `lake comparator --paranoid` have not been run, nor the standalone Comparator (v4.33.0), which the published record has end to end; and nothing here touches that record's second part, the proof combined with an independent formalization of Robin's criterion.
- No checker of X3 to X6 read a file of the proof that this repository made. They read the published copy of the export; what ties it to this repository's build is the comparison of size and SHA-256 in X1, made once. Of those checkers, only the kernel inside `lake comparator` ran in a sandbox. The counts of X3 (1,484,733), of X2 and X6 (1,468,418) and of C2 (1,478,243 constants) are made by different rules and have not been reconciled.
- The script behind X1 and X2 has been run once and has had no reviewer but the AI agent that wrote it. The one behind X3 to X6 has been run twice, once as a rehearsal on small stand-ins; an earlier state of it was reviewed by AI agents before either run, and it was changed afterwards (`records/cloud/kernel_check_review.json`). No person has reviewed either.

- Whether the result of the one full cloud run (`records/cloud/full-run/`) repeats. It is a single run on one kind of machine. Its records have been checked against each other by the scripts that wrote them and by AI agents, not yet by a person, and the Mac build that would be a second, independent C1 is unfinished.
- Whether the code that carried compiled files from the first cloud machine to the second after Google took the first back did so faithfully, beyond what the run itself checked: every part against its SHA-256, the parts against the sealed files (875,935 files, none missing, different or extra), and the kernel replay of every module afterwards, which reads those files.
- Whether Mathlib's definitions of the zeta function and of `RiemannHypothesis` say what is intended. They are Mathlib's, unmodified; this project has not audited them.
